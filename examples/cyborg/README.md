# VANGUARD M-07 · Hip-carry combat run

Стилизованный бронированный киборг с компактным автоматом. Авторская модель: шлем с визором и связью, отдельные грудные/плечевые/бедренные/голенные панели, сочленения, телескопические приводы коленей, ранцевый блок, пальцы и хват оружия. Броня следует за костями как жёсткие детали; две гибкие внутренние вставки ног используют настоящий линейный скиннинг.

## Посмотреть и редактировать

- `cyborg.gif` — 32 кадра, 20 FPS, два полных цикла бега. Разметка движется назад со скоростью виртуального продвижения; персонаж обращён и бежит вперёд по +Z.
- `cyborg.png` — крупный кадр модели в движении.
- `cyborg-viewer.html` — скачиваемый автономный HTML: вращение камеры, два клипа, таймлайн, каркас, отображение костной иерархии и скачивание GLB. Сервер и CDN не нужны. При ошибке WebGL виден сохранённый PNG. Интерактивный запуск в облачном Chromium остаётся непроверенным из-за ограничений песочницы.
- `cyborg.graph.json` — исходник для загрузки в Graph Forge; геометрия, материалы, кости, скиннинг, ключи и критерии проверки сохранены.
- `cyborg.glb` — экспорт для игрового движка: PBR-материалы, жёсткие детали, skin/joints/weights и два клипа.

Данные модели: 258 узлов, 16 костей, две skinned-сетки, 13 452 треугольника. Размеры заданы в метрах; стоящая модель примерно человеческого роста. +Y вверх, +Z вперёд. `manifest.json` содержит точные параметры.

## Анимация

`Combat run · in place`: 1,6 секунды, два цикла по 0,8 секунды; шаг 1,8 метра за цикл, виртуальная скорость 2,25 м/с. Редактор зацикливает этот клип.

`Combat run · root motion +Z`: те же позы с продвижением корня на 3,6 метра за 1,6 секунды. Редактор останавливается в конце; повторение и обработку root motion в игровом движке настрой отдельно.

Ключи запечены с шагом 1/240 секунды. Колени решаются через 3D two-bone IK с фиксированными длинами сегментов. Траектория таза согласует сжатие в опоре и баллистический полёт упрощённой точки массы. Стопа перекатывается по реальной подошве: посадка, плоская опора, отрыв через носок. Перенос ноги имеет ранний возврат пятки и подготовку к посадке; таз и грудь противовращаются. Это авторская кинематическая модель, не захват движения и не полная динамическая симуляция. Автомат удерживается двумя руками у правого бедра: корпус оружия примерно на 19–21 см выше тазового шарнира, правая кисть ниже него. Оружие анимируется независимо от груди. Поясница и грудная клетка имеют отдельные кости и разные упругие отклики на ритм опоры; голова компенсирует вращение корпуса. Руки каждый кадр решаются в мировых координатах к хватам, а концы приводов следуют за креплениями на бёдрах и голенях. Это художественная механическая конструкция, без расчёта сил всей модели и производственных допусков. Упругие отклики — отдельные скалярные каналы второго порядка; они не моделируют мышцы, инерцию всего персонажа или столкновения.

Стопа в переносе ориентируется относительно голени: при возврате пятки носок направлен вниз, а затем поднимается для подготовки к контакту. Колено, высота голеностопа и фактический просвет ботинка решаются совместно; подошва больше не удерживается горизонтальной в задней фазе. В опоре сохранён перекат с контролем пола.

Подробные принципы, вывод модели, ограничения и статус доступа к источникам: [RUNNING_MOTION.md](../../docs/RUNNING_MOTION.md). Параметры и выборка движения таза: `motion-style.json`. `run-before-after.gif` сравнивает предыдущий хват у бедра с исправленным движением голеностопа при одинаковой камере; `run-side.gif` показывает новый цикл сбоку (16 кадров, 20 FPS); `run-side-review.png` показывает восемь последовательных поз сбоку. Эти изображения позволяют оценивать механику, но сами по себе не доказывают естественность. `run-dynamics.png` показывает аналитическую вертикальную модель; это график заданного приближения, не измерение сил персонажа.

`front.png`, `side.png`, `back.png` — актуальная поза с трёх сторон. `run-upper-body.png` сравнивает заданные входы наклона с упругими откликами поясницы, груди и оружия.

`ankle-review.json` и `ankle-review.png` сравнивают реальные углы стопы и голени до/после с хешами исходников. Проекция сгибания — диагностика механического рига, не клиническая оценка. Памятка для будущих моделей: [GAIT_ANATOMY.md](../../docs/GAIT_ANATOMY.md).

## Проверено

`verification.json`: геометрия/атрибуты/skin buffers после GLB-импорта; отсутствие открытых и неманифолдных рёбер, конфликтов обхода и нулевых треугольников; мировые матрицы всех узлов и выборка деформированных вершин для обоих клипов; плотная проверка ботинок, длины конечностей, хвата и точек крепления приводов.

Измеренное скольжение текущих опорных точек — около 0,032 мм; максимальная ошибка по высоте в опоре — около 0,934 мм. Плотная выборка всей поверхности ботинок обнаруживает погружение до 0,097 мм между запечёнными ключами. При перекате проверяются актуальные участки подошвы, а не уже поднятая пятка. Эти значения отражают численную интерполяцию. Контакт/направление/полёт проходят заданные критерии; это кинематические проверки, а не оценка анатомии, баланса, всех столкновений или художественного уровня AAA.

`renderer-verification.json` отдельно сравнивает мировые границы шлема, кистей, ботинок и skinned-вставок в пяти кадрах между Graph Forge и Blender. Максимальное расхождение — менее микрометра.

Дополнительно проверяется высота оружия относительно таза, положение справа, запас до полного распрямления рук и мировая ориентация головы. Максимальная дистанция плечо–кисть — около 95,4% суммы длин плеча и предплечья; фиксация хвата не достигается растяжением рук.

PNG/GIF отрендерены **в Blender из настоящего GLB**, с его импортированной анимацией и скиннингом. Свет, пол, камера и разметка относятся к презентации и не включены в игровой GLB. Это не скриншот WebGL-редактора. Автомат — декоративная игровая модель. В этом примере используются одноцветные материалы, без нарисованных текстур, LOD и коллайдеров.

## Воспроизвести

Из корня репозитория с установленными npm-зависимостями. Для рендера нужен Blender 4.x, для GIF/архива — Python с Pillow. Matplotlib нужен только для необязательных диагностических графиков:

```bash
node scripts/build-cyborg.js
node scripts/verify-cyborg.js
node scripts/review-ankle.js examples/cyborg
# Для сравнения углов: передай сохранённый прежний .graph.json вторым аргументом.
blender -b --factory-startup --python scripts/verify-cyborg-blender.py -- examples/cyborg
blender -b --factory-startup --python scripts/render-cyborg.py -- examples/cyborg hero
blender -b --factory-startup --python scripts/render-cyborg.py -- examples/cyborg animate
blender -b --factory-startup --python scripts/render-cyborg.py -- examples/cyborg side-cycle
blender -b --factory-startup --python scripts/render-cyborg.py -- examples/cyborg views
node scripts/build-cyborg-viewer.js
python3 scripts/review-running.py examples/cyborg
# Для сравнения: передай сохранённый GIF прежней версии вторым аргументом.
# Необязательно: MPLCONFIGDIR=/tmp/graph-matplotlib python3 scripts/plot-running.py examples/cyborg
python3 scripts/package-cyborg.py
```

В ходе работы исправлена диагностика скорости скольжения: почти совпадающие key/contact times больше не превращают машинное округление позиции в ложную высокую скорость. Все положения по-прежнему проверяются; производная пропускает интервалы меньше относительной наносекунды. Регрессионный тест сохранён в `tests/model-review.test.js`.
