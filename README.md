# Graph Forge

Локальный 3D-редактор для создания игровых моделей и анимаций через визуальный интерфейс и команды агента. Three.js + Vite, без сервера данных и аккаунтов. Интерфейс на русском.

Редактор поддерживает импортированные и процедурные полигональные сетки, интерактивное редактирование компонентов, построение поверхностей SDF, объектную анимацию, векторный рисунок и пиксельные спрайты. Кистей скульптинга, UV/текстурной живописи, автоматического рига, кистей весов, физики и импорта произвольных GLB пока нет. Кости и линейный скиннинг поддерживаются; привязка и точные веса задаются через API. Художественное качество требует проверки реальных рендеров и доработки модели.

В версии **0.14** добавлено растворение внутренней вершины плоского выпуклого участка: на два треугольника меньше при сохранении контура, UV, цветов и заданных нормалей. Неоднозначные случаи отклоняются; перенос затронутого ориентира требует явного выбора. Диагностика поверхности теперь отдельно учитывает неиспользуемые вершины. [Применение и ограничения](docs/DISSOLVE.md).

Версия **0.13** добавила скруглённую фаску одного ребра: ширина вдоль соседних граней, 1–16 сегментов, радиальные нормали полосы и явный перенос затронутых ориентиров. Пока инструмент работает только на замкнутых выпуклых сетках без crease-тегов; фаски нескольких соседних рёбер ещё не поддерживаются. [Описание и воспроизводимый GLB-пример](docs/ROUNDED_BEVEL.md).

## Запуск

Демонстрационный комплект **HELIOS**: анимированный механический реактор, автономный HTML-просмотрщик, GLB, редактируемые 3D/2D-исходники, пиксельная иконка и векторная эмблема. [Файлы и воспроизведение](examples/helios/README.md). Презентационные PNG/GIF отрендерены из экспорта в Blender.

Нужны Node.js 22.12+ и npm.

```bash
npm ci
npm run dev
```

Открой адрес, который напечатает Vite. Для сборки: `npm run build`; для просмотра сборки: `npm run preview`. Браузеру нужен WebGL 2. Шрифты включены в сборку; приложение не обращается к внешним CDN. После установки зависимостей редактор работает без внешних API, ключей и сервисов.

## Возможности

- 3D-сцена с орбитальной камерой, студийным светом, процедурными отражениями окружения для PBR-материалов, тенями и сеткой.
- Куб, сфера, цилиндр, конус, тор, плоскость, капсула, тела вращения, выдавливание произвольного контура и группы. Родитель выбирается в свойствах; дерево поддерживает поиск и сворачивание ветвей.
- Скругление граней куба, настройка детализации, сглаживание и визуальный редактор профиля тела вращения: точки можно перетаскивать, добавлять, удалять и задавать числами.
- Манипулятор в мировых или локальных осях и привязка: перемещение 0.25 м, вращение 15°, масштаб 0.1. Поля трансформации в инспекторе всегда локальные.
- Выбор мышью и в дереве сцены; перемещение, вращение и масштаб через манипулятор или числовые поля.
- Материалы: цвет, шероховатость, металличность. Каркасный просмотр и скрытие объектов.
- Дублирование вместе с потомками, удаление поддеревьев, отмена и повтор (до 80 операций, с бюджетом истории около 64 МиБ) с восстановлением выбранного объекта и времени.
- Ключевые кадры положения, вращения и масштаба; таймлайн с переносом ключей мышью и переходами между ключами, выбор FPS, предпросмотр с зацикливанием. Положение и масштаб интерполируются линейно, вращение — quaternion slerp по кратчайшей дуге.
- JSON-проекты, немедленное автосохранение последней сцены в браузере, PNG-снимки без манипулятора и рамки выделения. Повреждённая локальная копия сохраняется отдельно и доступна для скачивания кнопкой восстановления.
- GLB: геометрия, материалы, иерархия и несколько независимых клипов анимации. Скрытые объекты и их потомки, редакторская сетка, свет и земля исключаются.
- Пакетные JSON-команды с проверкой: ошибочный пакет не применяется частично.

`W / E / R` — трансформации, `F` — фокус, `Пробел` — воспроизведение, `Shift D` — копия, `Delete` — удалить, `Ctrl/Cmd Z` — отменить, `Ctrl/Cmd Shift Z` — повторить, `Ctrl/Cmd S` — скачать проект, `[ / ]` — предыдущий/следующий ключ. `Escape` во время перетаскивания манипулятора отменяет текущий жест без создания записи в истории. ЛКМ с движением вращает камеру, ПКМ панорамирует, колесо меняет дистанцию.

Кнопка «Ключ» записывает все три трансформации выбранного объекта в текущем кадре. Если у объекта уже есть анимация, редактирование его трансформаций автоматически создаёт или заменяет ключ в текущем кадре. Для отключения анимации в конкретном клипе нужно удалить его ключи. В именованном клипе любая правка трансформации записывает ключ, даже если трек ещё пустой. Базовая поза при этом не меняется. Трансформации локальные; изменение родителя влияет на потомков, включая их масштаб. Поля вращения в интерфейсе показывают градусы; JSON/API используют радианы. Slerp не описывает полный оборот между одинаковыми ориентациями — для оборота добавь промежуточные ключи через 90–120°.

Изменения трансформаций в инспекторе блокируются на время воспроизведения, чтобы не записать случайно устаревшие поля. Перенос ключа округляется к кадру; перенос на занятое время отклоняется, а исходный ключ остаётся на месте. Изменение FPS не меняет время существующих ключей в секундах.

Автосохранение хранит одну сцену в `localStorage` этого браузера. Для надёжного переноса и нескольких проектов скачивай JSON. В GLB имена узлов соответствуют стабильным ID, отображаемое имя хранится в extras.label. Старые ключи узлов экспортируются как `Action`. Именованные клипы экспортируются отдельно; пустые клипы пропускаются. В каждом клипе объекты без собственного трека используют базовую позу, а не ключи другого действия. Экспорт предназначен для импорта в движок, JSON — для дальнейшего редактирования в Forge.

## Работа агента без ручных кликов

CLI использует ту же валидацию, геометрию и экспорт, что и редактор:

```bash
# Создать сцену Scout или пустой проект с --empty
node scripts/forge.js new /tmp/scout.graph.json

# Внести изменения атомарным пакетом
node scripts/forge.js apply /tmp/scout.graph.json examples/hover.json /tmp/hover.graph.json

# Проверить и экспортировать без браузера и GPU
node scripts/forge.js validate /tmp/hover.graph.json
node scripts/forge.js export /tmp/hover.graph.json /tmp/hover.glb

# Отрендерить кадр в PNG, здесь на секунде 2
node scripts/forge.js render /tmp/hover.graph.json /tmp/hover.png 2
```

Для `render` нужны devDependencies и Chromium. В этой облачной среде уже установлен `/usr/bin/chromium`; для другой машины задай `CHROMIUM_PATH`. CLI сам временно запускает Vite и закрывает его вместе с браузером после рендера. Software WebGL позволяет работать без GPU. Рендер содержит только 3D-сцену, без панелей и манипулятора. Для ассетов сохраняй и `.graph.json`, и `.glb`, проверяй PNG, затем исправляй исходную сцену пакетами команд.

### Формат команд

Пример `examples/hover.json` можно открыть и в диалоге «Команды».

```json
[
  {"op":"create","type":"group","id":"prop","name":"Game prop","position":[0,0,0]},
  {"op":"create","type":"box","id":"base","parent":"prop","name":"Base","position":[0,0.5,0],"scale":[2,1,1],"color":"#b8e986"},
  {"op":"update","id":"base","roughness":0.4,"metalness":0.2},
  {"op":"keyframe","id":"prop","time":0,"rotation":[0,0,0]},
  {"op":"keyframe","id":"prop","time":2,"rotation":[0,1.5,0]}
]
```

Операции:

| `op` | Поля и поведение |
| --- | --- |
| `create` | `type`, необязательные `id`, `name`, `parent`, `position`, `rotation`, `scale`, `color`, `roughness`, `metalness`, `visible`, `geometry`, `keys`. Родитель по умолчанию `null`, позиция `[0,0.5,0]`, масштаб `[1,1,1]`. |
| `update` | `id` и изменяемые поля из предыдущей строки, кроме `type`, `id`, `keys`. Переподчинение сохраняет локальную трансформацию. Изменение базовой позы через команды не меняет уже существующие ключи. |
| `delete` | `id`; удаляет объект и всех потомков. |
| `keyframe` | `id`, `time`, необязательные `position`, `rotation`, `scale`. Пропущенные поля берутся из вычисленной позы в это время. Ключ с таким временем заменяется. |
| `moveKeyframe` | `id`, `from`, `time`: переносит существующий ключ; занятое время вызывает ошибку без изменения проекта. |
| `removeKeyframe` | `id`, `time`. |
| `scene` | Необязательные `name`, `duration` (0.1–600 секунд), `fps` (1–120). Нельзя сократить длительность за существующие ключи. |

Примитивы: `box`, `sphere`, `cylinder`, `cone`, `torus`, `plane`, `capsule`, `lathe`, `extrude`, `group`. Куб и плоскость имеют размер 1; сфера, цилиндр и конус — радиус 0.5, высота цилиндра/конуса 1; тор — основной радиус 0.5 и радиус трубки 0.15. Цилиндр и конус направлены по Y, плоскость лежит в XY. Капсула имеет радиус 0.25 и полную высоту 1. Тело вращения строится вокруг Y по массиву `geometry.profile` из 2–128 точек `[radius, height]`; радиус 0 замыкает торец. Радиус допустим от 0 до 100, высота от −100 до 100. Без профиля используется стандартный контур сосуда. `geometry.bevel` скругляет куб (0–0.49), `geometry.bevelSegments` задаёт детализацию скругления (1–8, по умолчанию 3). Скругление задаётся в локальной геометрии: неравномерный масштаб меняет форму скругления. `geometry.smooth` включает/выключает плавное сглаживание; по умолчанию оно включено у сферы, капсулы, тела вращения и скруглённого куба. `geometry.segments` задаёт детализацию целым числом 3–96 (по умолчанию 32), `geometry.tube` — радиус трубки тора 0.01–1. Масштаб должен быть положительным. Цвет — hex `#rrggbb`. Идентификаторы уникальны, до 100 символов `[a-zA-Z0-9_-]`. До 2000 объектов и 2000 ключей на объект; большие сцены могут замедлять интерфейс.

Проект — JSON `{ "version": 1, "name": "...", "duration": 4, "fps": 24, "nodes": [...] }`. Полный пример: `examples/scout.graph.json`. Все поля узла представлены в примере. Формат проверяется до замены открытой сцены.

### API браузера

Доступен после загрузки редактора:

```js
window.forge.getDocument()      // независимая копия JSON-проекта
window.forge.execute(commands)  // пакет с одной операцией отмены
window.forge.load(document)     // проверить и открыть JSON, сбросить время
window.forge.select('body')
window.forge.selectMany(['body','head']) // последний — активный объект
window.forge.transformSelection({position:[1,0,0], rotation:[0,0.3,0], scale:[1,1,1]}) // мировые оси, общий центр
window.forge.importOBJ(objText, {name:'Imported prop'}) // добавить в текущую сцену, вернуть {ids,warnings}
window.forge.setClip('swing')   // выбрать именованный клип; null или 'default' — Action
window.forge.seek(1.5)          // секунды, останавливает воспроизведение
window.forge.getPose('body')    // текущая локальная поза
window.forge.getView()          // камера, цель, выбранный ID, время, воспроизведение, activeClip
window.forge.project([0,1,0])   // мировая точка -> координаты CSS в окне {x,y}
window.forge.focus()            // фокус на выбранном объекте или всей сцене
window.forge.undo()
window.forge.redo()
window.forge.screenshot()       // PNG data URL только 3D-вида
await window.forge.exportGLB()  // ArrayBuffer + скачивание GLB
```

Пользовательский JavaScript не исполняется из JSON. Автоматизация возможна через Playwright `page.evaluate`, а создание/экспорт ассетов — напрямую через CLI.

## Проверки

```bash
npm test                 # валидация, иерархия, транзакции, анимация
npm run test:e2e         # Chromium: UI, манипулятор, сохранение, GLB, компактный экран
npm run build
```

E2E используют системный Chromium или `CHROMIUM_PATH`, запускают собственный сервер Vite и включают software WebGL. Кадры диагностики сохраняются в `/tmp/graph-forge-desktop.png` и `/tmp/graph-forge-mobile.png`. Существующий пользовательский сервер можно оставить: тесты используют изолированные контексты браузера. Готовую сборку можно разместить на обычном статическом хостинге; публикация в этом задании не выполнялась.

## Выдавливание контура

Тип `extrude` строит объёмную модель из замкнутого многоугольника в плоскости XY. `geometry.outline` — 3–128 точек `[x,y]` (координаты −100…100), `geometry.depth` — толщина вдоль Z (0.001–100, по умолчанию 0.2). Объём центрирован по Z, передняя и задняя плоскости находятся на `±depth/2`. Последнюю точку повторять не нужно: контур замыкается автоматически. Поддерживаются выпуклые и вогнутые формы, но не отверстия, самопересечения, перекрывающиеся рёбра или нулевая площадь. Скругление экструзии пока не поддерживается. Это полезно для клинков, щитов, панелей и других деталей со сложным силуэтом.

В свойствах выбери «Редактировать контур»: точки перемещаются мышью либо числовыми полями X/Y; добавление точки вставляет середину следующего ребра. Ошибочный контур остаётся в диалоге для исправления и не меняет проект. Применение всего контура — одна операция отмены.

```json
[{"op":"create","type":"extrude","id":"blade","geometry":{"depth":0.08,"outline":[[-0.2,0],[0.2,0],[0.3,1.5],[0,2],[-0.3,1.5]]}}]
```

## Независимые клипы анимации

Селектор слева на таймлайне переключает действие, кнопка «…» открывает библиотеку клипов. Можно создать, переименовать, дублировать или удалить именованный клип и задать его длительность. `Action` — совместимый со старыми проектами основной клип, его удалить или переименовать нельзя. FPS общий для проекта, длительность и ключи независимы. Выбор клипа сбрасывает время; история изменений восстанавливает и выбранный клип. После загрузки проекта выбирается `Action`.

Именованные клипы добавляются к формату v1 необязательным полем `clips`: массив `{id,name,duration,tracks}`, где `tracks` — объект `{nodeId: [keyframes]}`. Старые проекты без этого поля не требуют миграции. Допускаются 32 именованных клипа; имена уникальны, до 100 символов, `Action` зарезервировано. ID клипа использует те же символы, что ID объекта; `default` зарезервировано для основного клипа.

| Команда | Параметры |
| --- | --- |
| `createClip` | `id` (необязательный UUID), `name`, `duration` (по умолчанию длительность Action), необязательные `tracks`. |
| `duplicateClip` | `id` нового клипа, `name`, `source` (ID источника; без него или `default` копируется Action). |
| `updateClip` | `id`, необязательные `name`, `duration`; ключи за новой границей времени вызывают ошибку. |
| `deleteClip` | `id` именованного клипа. Удаление можно отменить в редакторе. |
| `keyframe`, `moveKeyframe`, `removeKeyframe` | Дополнительное поле `clip` выбирает именованный клип; без него или с `default` редактируется Action. |

```json
[
  {"op":"createClip","id":"swing","name":"Swing","duration":1.4},
  {"op":"keyframe","id":"blade","clip":"swing","time":0,"rotation":[0,0,0.6]},
  {"op":"keyframe","id":"blade","clip":"swing","time":0.7,"rotation":[0,0,-0.9]},
  {"op":"keyframe","id":"blade","clip":"swing","time":1.4,"rotation":[0,0,0.6]}
]
```

Удаление объекта удаляет его треки из всех клипов; дублирование объекта в интерфейсе копирует и его анимацию во всех клипах. API `update` по-прежнему меняет базовую позу, а не ключи — для анимационных правок из команд используй `keyframe` с нужным `clip`.

CLI-рендер поддерживает ID клипа после времени:

```bash
node scripts/forge.js new /tmp/empty.graph.json --empty
node scripts/forge.js apply /tmp/empty.graph.json examples/verdant-blade.json /tmp/sword.graph.json
node scripts/forge.js export /tmp/sword.graph.json /tmp/sword.glb
node scripts/forge.js render /tmp/sword.graph.json /tmp/sword.png 1 idle
```

Готовый пример: `examples/verdant-blade.graph.json`, `examples/verdant-blade.glb` и `examples/verdant-blade.png`. Пакет `examples/verdant-blade.json` создаёт меч с выдавленным клинком и независимыми действиями `Idle` и `Swing`. Костный риг и скульптинг по-прежнему не входят в текущую версию.

## Сборка моделей и множественное выделение

Shift + клик в дереве или по модели добавляет/убирает объект. Ctrl/Cmd + A выбирает все видимые объекты сцены, Escape сбрасывает выделение. Последний выбранный объект активен: его трек показывается на таймлайне. Список `getView().selectedIds` хранит всё выделение, `selected` остаётся ID активного объекта для совместимости.

При нескольких объектах общий манипулятор перемещает, вращает и масштабирует их относительно центра видимых границ выделения. Его базис совпадает с мировыми осями; локальные оси сохраняются для одиночного объекта. Если выделены родитель и потомок, преобразуется только родитель — потомок наследует движение один раз. Сдвиг в числовых полях панели выделения задан в мировых метрах. Общий цвет меняет только явно выбранные сетки, не всех потомков выбранных групп. Кнопка «Ключ» записывает локальные позы всех выбранных объектов; кнопка удаления ключа на таймлайне относится к показанному активному треку.

Ctrl/Cmd + G создаёт группу, Ctrl/Cmd + Shift + G разбирает выбранные группы. То же доступно кнопками под поиском. Выбранные корневые объекты должны иметь одного родителя: тогда группировка точно сохраняет все действия и промежуточные позы. Pivot новой группы — среднее базовых локальных положений её детей. Неизменяемый родитель может иметь собственную анимацию.

Разгруппировка переносит статическую трансформацию группы в базовые позы и ключи детей. Анимированную группу нельзя разобрать без запекания; неравномерно масштабированную группу с анимированными детьми также нельзя разобрать. Если преобразование создаёт shear (сдвиг осей), который нельзя представить обычными положением/вращением/масштабом, операция целиком отклоняется. Это предотвращает незаметное искажение модели или анимации. Отмена жеста манипулятора через Escape возвращает исходную сцену.

Shift + D и Delete работают со всем выделением и поддеревьями. Копирование сохраняет треки каждого клипа. Смещение копии по умолчанию — `[1.5,0,0]` в локальных осях родителя каждого корня; для общего мирового перемещения используй манипулятор. Все пакетные действия — одна операция отмены, вместе с полным выделением, временем и активным клипом. Для больших импортированных моделей история может хранить меньше 80 операций из-за ограничения памяти.

Команды агента:

```json
[
  {"op":"group","id":"upper-body","ids":["body","head"],"name":"Upper body"},
  {"op":"duplicate","ids":["upper-body"],"offset":[2,0,0]},
  {"op":"ungroup","id":"upper-body"}
]
```

У `duplicate` можно задать `idMap` — объект `{oldId:newId}` для стабильных ID копий; отсутствующие ID генерируются автоматически. Группировка и копирование одинаково работают через API/CLI и интерфейс.

## Импорт OBJ

Кнопка «Импорт OBJ» добавляет геометрию в текущую сцену под новым корневым объектом, сохраняя уже существующие модели и клипы. Поддерживаются `v`, `vt`, `vn`, `f`, `o`, `g`, `s`, `usemtl`, `mtllib`. Отрицательные индексы, однородные координаты вершин и вогнутые плоские многоугольники учитываются. Объекты и слоты материалов становятся отдельными сетками. Самопересекающиеся, вырожденные и неплоские грани отклоняются; неплоские многогранники нужно сначала триангулировать в исходной программе. Одна грань может содержать до 128 точек.

MTL и текстуры **не загружаются**. Имена материалов сохраняются в названиях сеток, цвет можно задать в редакторе. Линии, точки и дополнительные цветовые атрибуты вершин пропускаются с предупреждением в API/CLI. Файлы NURBS/кривых не поддерживаются. Сохранённые UV и нормали переходят в JSON и GLB; недостающие нормали вычисляются с учётом smoothing groups, включая непрерывность на UV-швах и между слотами материалов. Если UV заполнены не у всех вершин части, UV этой части пропускаются с явным предупреждением; остальные части сохраняют полные UV. Координаты и единицы не преобразуются, редактор интерпретирует их как метры и Y-up.

Ограничения: текстовый OBJ до 10 МиБ, до 100 000 вершин и 100 000 треугольников на сетку, до 250 000 импортированных вершин и треугольников суммарно в сцене. Индексированные данные хранятся как тип `mesh`: `geometry.positions`, `geometry.indices`, необязательные `geometry.normals`, `geometry.uv`. Все массивы проверяются до замены проекта. Сетки можно трансформировать, группировать, анимировать и менять их материалы; редактирования отдельных вершин пока нет.

```bash
node scripts/forge.js import-obj examples/stone-gate.obj /tmp/gate.graph.json
node scripts/forge.js export /tmp/gate.graph.json /tmp/gate.glb
node scripts/forge.js render /tmp/gate.graph.json /tmp/gate.png
```

Готовый пример импорта: `examples/stone-gate.graph.json`, `examples/stone-gate.glb` и `examples/stone-gate.png`. Исходный OBJ включает вогнутые грани и отдельную подставку.

Импорт в CLI создаёт новый проект; импорт в интерфейсе/API добавляет модель в открытый проект. Внешние файлы по ссылкам из OBJ не читаются и сетевые запросы не выполняются.

## CINDER — бегущий горящий демон

В левой панели нажми **CINDER · Горящий демон**: пример загрузится с выбранным клипом `Run` и начнёт воспроизведение. Пробел — пауза; предыдущая сцена остаётся в истории отмены. Загрузка примера заменяет текущую сцену, поэтому для отдельной постоянной копии сначала сохрани свой проект.

`examples/cinder-demon.graph.json` — редактируемый источник. `examples/cinder-demon.glb` — модель с материалами, иерархией и клипом `Run` для движка. Это стилизованный демон: мышцы и панцирь, четыре изогнутых рога, клыки, пальцы с когтями, раздвоенные копыта, семисегментный хвост, лавовые трещины, языки огня и искры. Модель смотрит вдоль +Z, Y — вверх; один цикл бега на месте длится 0,88 секунды. Для перемещения персонажа в игре нужно двигать его корневой объект.

Анимация использует шарниры из групп и локальные трансформации, без костного рига и скиннинга. Пламя и искры — анимированная геометрия, которая экспортируется вместе с персонажем. Это не симуляция частиц; свечение материалов само по себе не освещает соседние поверхности. Для ореола вокруг огня в игровом движке можно включить bloom. Текстуры и внешние ресурсы модели не нужны.

В свойствах материала доступны **Цвет свечения** и **Сила свечения** (0–20). В JSON и командах это `emissive: "#ff4000"` и `emissiveIntensity: 3`. Старые проекты без этих полей получают нулевое свечение. Экспорт сохраняет яркие материалы через `KHR_materials_emissive_strength`; для полной яркости нужен движок с поддержкой этого расширения.

Воспроизведение сборки и экспорта:

```bash
node scripts/build-demon.js
node scripts/forge.js validate examples/cinder-demon.graph.json
node scripts/forge.js export examples/cinder-demon.graph.json examples/cinder-demon.glb
node scripts/forge.js render examples/cinder-demon.graph.json /tmp/cinder.png 0.08 run
```

`node scripts/render-demon-preview.js` сохраняет скриншот интерфейса, чистый PNG и 32 кадра реального редактора в `/tmp/cinder-frames`. Кадры имеют фиксированную камеру. Для ролика с пятью повторениями цикла в исходном темпе:

```bash
ffmpeg -y -framerate 400/11 -i /tmp/cinder-frames/%03d.png -vf "loop=loop=4:size=32:start=0,setpts=N*11/(400*TB)" -frames:v 160 -c:v libx264 -pix_fmt yuv420p -movflags +faststart examples/cinder-demon-run.mp4
```

Автоматическая проверка сравнивает мировые матрицы исходной сцены и повторно загруженного GLB в течение цикла, проверяет замыкание ключей, фазу полёта и отсутствие проваливания копыт под землю. PNG и GIF предпросмотра получены захватом кадров в Graph Forge.

## Версия 0.5: цельные поверхности, 2D и Pixel

Кнопки **Органическая сетка** и **2D / Pixel** находятся в верхней панели. Это отдельные способы создавать игровые ассеты: органическая поверхность выпекается в одну сетку; 2D хранит редактируемые кривые; Pixel хранит точные индексы палитры для каждого кадра и слоя.

### Органические поверхности

В диалоге редактируется рецепт SDF: эллипсоиды и капсулы плавно объединяются (`union`) или вырезают материал (`subtract`). Внутренние объёмы служат инструментами построения: результат состоит из общих вершин и треугольников, а не из пересекающихся видимых примитивов. Поддерживаются поворот эллипсоида, плавность соединения, сужение капсулы и цвет каждого поля. Цвета смешиваются на поверхности и экспортируются как линейный RGB `COLOR_0` в GLB.

Генерация предпросмотра выполняется в Worker и не изменяет документ. **Добавить сетку** — одна операция отмены. Исходный рецепт остаётся в `node.sculpt`; кнопка в свойствах позволяет перестроить поверхность. Изменение рецепта сбрасывает готовность предпросмотра: сначала нужно пересчитать геометрию. Ошибки и отмена диалога не меняют проект. Поверхность должна полностью помещаться в `bounds`; границы, пересекающие модель, отклоняются.

**Warden · Цельная сетка** в левой панели загружает готовый пример: единая поверхность бюста с шеей, рогами, резными углублениями и окраской вершин; глаза — отдельные вставки. Файлы: `examples/warden.sculpt.json`, `examples/warden.graph.json`, `examples/warden.glb`, `examples/warden.png`. Рецепт можно также открыть кнопкой **Пример Warden** в диалоге органической сетки.

```bash
node scripts/forge.js sculpt examples/warden.sculpt.json /tmp/surface.graph.json
node scripts/forge.js export /tmp/surface.graph.json /tmp/surface.glb
```

Команда для агента:

```js
window.forge.execute([{
  op: 'sculpt', id: 'body', name: 'Continuous body', position: [0, 0, 0],
  recipe: {
    version: 1, resolution: 32,
    bounds: [[-1.5,-1.5,-1.5],[1.5,1.5,1.5]],
    parts: [
      {shape:'ellipsoid',center:[0,0,0],radius:[.7,.8,.5],smooth:.2,color:'#52796c'},
      {shape:'capsule',a:[0,.4,0],b:[.7,.7,0],radius:.25,endRadius:.08,smooth:.2,color:'#8bab91'}
    ]
  }
}]);
```

Если `id` уже принадлежит сетке, `sculpt` заменяет её геометрию и рецепт, сохраняя трансформации и действия. Диапазон разрешения — 12–96 ячеек по самой длинной стороне; до 64 полей, четырёх перестроений в одном пакете, 100 000 вершин и 100 000 треугольников на результат. Общие бюджеты сцены продолжают действовать. Рецепт надо сохранять отдельно, если нужна воспроизводимая генерация вне редактора. Сглаженная поверхность не заменяет ручную ретопологию персонажа: инструмент не создаёт костей, скиннинга или UV-развёртки автоматически.

### Pixel: спрайты и анимация

**Новый Pixel** создаёт холст с прозрачным фоном. Работают непрерывные штрихи пера, ластик, четырёхсвязная заливка, зеркальная кисть, палитра, слои с видимостью/непрозрачностью и изменением порядка. Размер холста можно менять с сохранением существующих пикселей слева сверху; увеличение добавляет прозрачную область, уменьшение обрезает рисунок. Масштаб предпросмотра не меняет исходное разрешение.

Кадры можно копировать, добавлять пустыми, удалять и задавать каждому длительность в миллисекундах. Доступны воспроизведение, предыдущий кадр полупрозрачным слоем и отмена/повтор. Покадровый экспорт **PNG кадра** сохраняет прозрачность; **PNG атласа** и **JSON атласа** дают спрайт-лист и координаты. Метаданные используют структуру кадров Aseprite JSON Array (`filename`, `frame`, `sourceSize`, `spriteSourceSize`, `duration`, `meta.frameTags`). Это формат данных для импорта; отдельные интеграции с игровыми движками не включены.

Пример **Ranger** — персонаж 64 × 64 с плащом, бронёй и клинком, восемь кадров бега. Готовые файлы: `examples/ranger.art.json`, `examples/ranger-atlas.png`, `examples/ranger-atlas.json`, `examples/ranger-run.gif` и `examples/ranger.png`.

PNG можно импортировать как новый пиксельный проект, если он содержит не больше 256 цветов и имеет размер до 256 × 256. Если цветов больше, импорт отклоняется без скрытого ухудшения изображения. Нулевой цвет палитры — прозрачный `#00000000`.

### 2D: кривые и иллюстрации

**Новый 2D** создаёт векторный холст 512 × 512. Перо записывает сглаженные квадратичные кривые; панель контуров позволяет точно редактировать путь, заливку, линейные градиенты, обводку и прозрачность. Контуры задаются массивами `M`, `L`, `C`, `Q`, `Z`; внешние изображения, шрифты, скрипты и сетевые ссылки не используются. Слои, кадры, история, PNG и атласы доступны так же, как в Pixel. Кнопка **SVG** сохраняет масштабируемый рисунок.

Пример **Rune** — клинок Tideglass с градиентным металлом, гравировкой, обмоткой рукояти и магическими лентами. Исходник: `examples/tideglass.art.json`; готовые экспорты: `examples/tideglass.svg` и `examples/tideglass.png`. В этой версии нет интерактивного редактирования ручек Безье: точная правка идёт через панель контуров/API.

2D-проекты сохраняются отдельно от 3D в `graph-forge-art-project`. Файл **Сохранить проект** содержит слои и все кадры; PNG/SVG — готовые изображения. Недоступность localStorage не блокирует файловый экспорт; повреждённое автосохранение можно скачать для восстановления. История хранит до 24 изменений с бюджетом около 32 МиБ. Ограничения: 64 кадра, 16 слоёв на кадр; Pixel до 256 × 256 и 4 млн ячеек суммарно; Vector до 2048 × 2048, 4096 путей и 65 536 команд; атлас не больше 8192 × 8192.

### API и воспроизводимая сборка

```js
window.forge.openArt(artDocument); // открывает отдельную мастерскую
window.forgeArt.getDocument();    // копия редактируемого 2D-документа
window.forgeArt.load(artDocument);
window.forgeArt.seek(3);          // индекс кадра с нуля
window.forgeArt.exportPNG();      // data URL текущего кадра
window.forgeArt.exportSVG();      // только для Vector
window.forgeArt.exportAtlas({columns:4,padding:2}); // {png, metadata}
window.forgeArt.undo();
window.forgeArt.redo();
```

Чистые операции без DOM находятся в `src/art-document.js`: `validateArt`, `emptyArt`, `paintLine`, `floodFill`, `compositePixels`, `frameSVG`, `atlasLayout`. Рендерер Canvas 2D — `src/art-render.js`. CLI использует тот же рендерер; экспорт 2D не запускает 3D-сцену и не требует WebGL.

```bash
node scripts/build-asset-pack.js
node scripts/forge.js export examples/warden.graph.json examples/warden.glb
node scripts/forge.js art-export examples/ranger.art.json examples/ranger-atlas.png --atlas
node scripts/forge.js art-export examples/ranger.art.json examples/ranger.png 1
node scripts/forge.js art-export examples/tideglass.art.json examples/tideglass.svg
node scripts/forge.js art-export examples/tideglass.art.json examples/tideglass.png
```

Проверки покрывают замкнутость сетки и ориентацию нормалей, реальное вырезание материала, сохранение цвета вершин в GLB, точность пикселей и прозрачности, зеркальную кисть, заливку, слои, историю, изменение размера холста, безопасный SVG и координаты атласа. Эти инструменты расширяют создание игровых ассетов, но редактор пока не заменяет полный DCC-пакет: ручная ретопология, костный риг, скиннинг и UV/текстурная живопись остаются отдельными задачами.

У Warden также есть `examples/warden-low.graph.json` / `examples/warden-low.glb` для дальнего плана. Оба варианта используют один рецепт с разным разрешением; переключение LOD настраивается в игровом движке. Состав пакета, пути к файлам, оси и размеры перечислены в `examples/asset-pack.json`.

В рецепте `keepLargestSurface: true` оставляет основную связную оболочку и удаляет целые изолированные фрагменты. Эта настройка включена в примере Warden и полезна при выпекании облегчённого варианта; для намеренно раздельных поверхностей её следует выключить. Базовый цвет материала умножается на окраску вершин, поэтому для исходной палитры используется белый материал.

Большие 3D-проекты могут превышать квоту localStorage браузера: редактор показывает «Не сохранено · скачай JSON». Для постоянной копии сохраняй исходник в файл; экспорт GLB сохраняет готовую модель, но не рецепт построения. CLI и исходники в `examples/` не зависят от браузерной квоты.

GIF-превью Ranger получено из настоящих кадров атласа, увеличенных ближайшим соседом:

```bash
ffmpeg -y -framerate 25/2 -i examples/ranger-atlas.png -filter_complex 'loop=loop=7:size=1:start=0,crop=64:64:1+66*mod(n\,8):1,scale=256:256:flags=neighbor,split[a][b];[a]palettegen=reserve_transparent=1[p];[b][p]paletteuse=dither=none' -frames:v 8 -loop 0 examples/ranger-run.gif
```


## Проверка формы и движения

Кнопка **Asterion · Точная модель** открывает новый 3D-меч: профильный клинок с фасками, изогнутая гарда, вставки и спиральная обмотка рукояти. Исходник `examples/asterion.graph.json`, игровой экспорт `examples/asterion.glb`, реальный рендер `examples/asterion.png`. Все 12 сеток имеют закрытые оболочки и согласованный порядок граней; основные детали симметричны по локальной X, обмотка намеренно асимметрична. Это статическая предметная модель.

В верхней панели доступны **Материалы**, **Силуэт** и **Нормали**. Кнопка **Проверка сетки** показывает открытые рёбра, ошибки соединений, ориентацию нормалей и долю зеркальных вершин. Совпадающие позиции объединяются для проверки независимо от швов UV и жёстких нормалей. Открытая поверхность или асимметрия не всегда являются ошибкой; отчёт не оценивает красоту или качество UV.

Пол студии по умолчанию находится на **Y = 0**. В проверке сетки можно задать высоту или нажать **Пол под моделью**. Для оружия с началом координат на рукояти это позволяет показать весь предмет. Настройки пола, камеры и отображения не меняют исходник и GLB.

Точный API для работы агента:

```js
forge.setView({preset: 'front'}); // front, back, right, left, top, threeQuarter
forge.setView({camera: [-6, 3, 5], target: [0, 1.6, 0], fov: 40});
forge.setStage({groundY: 0});
forge.setStage({fit: true}); // пол под текущей моделью
forge.setShading('silhouette'); // material, silhouette, normals
const statistics = forge.inspect();
const views = forge.captureViews({
  presets: ['front', 'right', 'back', 'threeQuarter'], surface: 'material'
}); // {preset, camera, target, fov, png}[]; восстанавливает прежний вид
```

Для Pixel кнопка **Проверка бега** показывает два синхронных варианта: бег на месте с движущейся землёй и продвижение по неподвижной земле. **Отразить всю анимацию** зеркалит все кадры, градиенты и опорные точки одним шагом истории. Ranger исправлен: взгляд и продвижение вправо, опорная стопа движется назад относительно корпуса. Суставы рассчитываются двухзвенной IK с постоянной длиной сегментов.

Опциональный `art.motion` хранит `version: 1`, `kind: 'run'`, `facing: 'right'|'left'`, `distance` (пикселей за цикл), `groundY`, `feet: [{id, points: [[x,y], ...], contact: [boolean, ...]}]`. Массивы соответствуют кадрам. Проверка измеряет скольжение опорных точек, высоту опоры, направление и наличие полёта. Она проверяет заданные точки, а не распознаёт ноги в рисунке. После изменения рисунка точки нужно перепроверить. Метаданные сохраняются в `meta.motion` атласа. Текущий отчёт: `examples/ranger-motion-report.json`; наибольшее отклонение опоры — 0.5 px из-за округления до пиксельной сетки.

У демона два независимых клипа: **Run** на месте и **Run forward** с продвижением на 2.9 м по +Z за 0.88 с. Лицо направлено по +Z, верх по +Y. Стопы в фазе опоры остаются на Y = 0; анимация корпуса больше не наклоняет весь корень вместе с опорными ногами. `loop: false` у именованного клипа останавливает проигрыватель редактора в последнем кадре. GLB экспортирует движение корня, но настройку зацикливания нужно задавать в игровом движке.

Воспроизведение проверки и реальных кадров:

```bash
node scripts/build-demon.js
node scripts/build-asterion.js
node scripts/forge.js export examples/asterion.graph.json examples/asterion.glb
node scripts/render-quality-review.js /tmp/graph-quality
node scripts/render-demon-preview.js
ffmpeg -y -framerate 12.5 -i /tmp/graph-quality/ranger-motion/%03d.png -filter_complex '[0:v]split[a][b];[a]palettegen[p];[b][p]paletteuse=dither=bayer' -loop 0 examples/ranger-motion-review.gif
```

Просмотр реальных ракурсов и покадровая проверка обязательны для дальнейших моделей. Успешный экспорт и отсутствие открытых рёбер сами по себе не подтверждают художественное качество.


## Версия 0.6: скелет и проверка деформации

По запросу художественные модели отложены. Эта итерация развивает редактор; **Стенд скиннинга** — техническая проверка сгиба, не новый персонаж. Разбор спецификации и критерии следующего персонажа: [docs/RIGGING_PIPELINE.md](docs/RIGGING_PIPELINE.md).

Объект `bone` создаёт настоящую кость Three.js. Иерархия и ключи работают так же, как у объектов. Сетка может хранить `skin: {joints, indices, weights, bindMatrix, inverseBindMatrices}`: палитра до 256 костей с корнем первой, четыре индекса и четыре веса на вершину, сумма весов 1. Все промежуточные кости входят в палитру. Матрицы — массивы column-major по 16 чисел; обратные матрицы — массив таких матриц в порядке `joints`.

Привязка сохраняет матрицы базовой позы один раз. Поворот костей после привязки деформирует сетку. Не привязывай заново при каждом кадре. Для перемещения персонажа выбирай общий корень рига; трансформации и анимация непосредственно сетки со скиннингом блокируются. Копировать нужно весь риг: палитра ссылок будет переназначена, матрицы привязки сохранятся.

```js
forge.execute([{
  op: 'bindSkin', id: 'body',
  joints: ['hips', 'spine', 'chest'],
  indices: jointIndices, // 4 на вершину; индексы в joints
  weights: jointWeights // 4 на вершину, сумма 1
}]);
forge.execute([{
  op: 'setSkinWeights', id: 'body', vertices: [12, 13],
  influences: [{joint: 'hips', weight: 0.25}, {joint: 'spine', weight: 0.75}]
}]);
forge.setRigVisible(true);
forge.select('spine');
forge.setShading('weights'); // синий 0 → оранжевый 1
const cleanPNG = forge.screenshot(); // кости и манипуляторы скрыты
const rigPNG = forge.screenshot({rig: true});
const check = forge.auditRig({clip: 'run', samples: 121});
const pose = forge.sampleRig({clip: 'run', time: 0.2, mesh: 'body', vertices: [12, 13]});
```

Кнопка **Проверка рига** проверяет выбранный клип: изменение длины сегмента в локальных координатах, анимированный масштаб кости и заданные ограничения. Помимо равномерной сетки проверяются все ключи костей (общий предел — 4096 моментов). Кнопка кости в отчёте открывает первый найденный проблемный момент. Если ограничение не задано, отчёт так и пишет; отсутствие ошибки не означает правильную анатомию.

Ограничение шарнира задаётся в инспекторе кости или как `jointLimit: {axis: 'x', min: 0, max: 135, swing: 5}`. Числа — градусы относительно базового `node.rotation`: диапазон поворота вокруг одной оси и допуск поворота вне неё. Пример диапазона произвольный, не анатомический норматив. Проверка предупреждает, но не зажимает движение автоматически. Одного шарнира недостаточно для плеча, таза и других сложных суставов.

GLB содержит настоящие `skins`, `JOINTS_0`, `WEIGHTS_0`, обратные матрицы и анимацию костей. Проверки сравнивают деформированные вершины после обратного импорта, включая произвольную привязку и смещение корня. Поддерживается линейный скиннинг; потеря объёма на сгибе и скручивании остаётся его ограничением. Кисти весов, корректирующие формы, ретаргетинг и автоматический риг пока не реализованы. `unbindSkin` удаляет привязку и возвращает исходную геометрию; текущую деформацию в вершины он не запекает.


Проверка рига без браузера: `node scripts/forge.js audit-rig project.graph.json run`. Команда печатает JSON; код выхода 0 означает отсутствие найденных нарушений заданных правил, 2 — найденные нарушения, 1 — некорректный вход. Для статической сцены без костей массив `bones` будет пустым; это не проверка анатомии. Реальные снимки стенда воспроизводятся через `node scripts/render-rig-review.js /tmp/graph-rig-review`.


## Версия 0.7: ориентиры, пропорции и 3D-опора

**Контроль модели** открывает лабораторию измерений и движения. Ориентиры можно задать на костях, жёстких объектах и конкретных деформируемых вершинах. Измеряются расстояния, отношения и отклонения от зеркальной симметрии относительно выбранной плоскости. Диапазоны задаются по референсу конкретной модели; универсальные «идеальные» пропорции не назначаются.

Анализ 3D-движения отдельно проверяет скольжение точек опоры, высоту контакта, провал подошвы, продвижение и ход корня назад, направление траектории и взгляда, а также заданную фазу полёта. Для анимации на месте можно задать виртуальное продвижение. Оно применяется только в анализе. Графики показывают реальные измерения и указанное расписание контактов; отчёт переводит к проблемному кадру.

Критерии хранятся в `document.review`, сохраняются одним шагом истории и восстанавливаются вместе с проектом. Некорректный черновик очищает предыдущий отчёт. Ориентиры и линии отображаются только в редакторе; обычный PNG и GLB их исключают.

```js
forge.execute([{op:'setReview', review: criteria}]);
forge.auditMeasurements(); // базовая поза
forge.auditMeasurements({pose:'clip', clip:'run', time:0.2});
forge.auditLocomotion({clip:'run'});
forge.auditLocomotion({clip:'run-in-place', mode:'inPlace', distance:2.9});
forge.setReviewVisible(true);
forge.screenshot({review:true});
```

CLI: `node scripts/forge.js audit-model project.graph.json [clip-id]`. Полная схема, изученные источники OpenSim и границы проверок: [docs/MEASUREMENTS_AND_MOTION.md](docs/MEASUREMENTS_AND_MOTION.md).

Технический стенд опоры проверяет траектории блоков. Он не является художественным персонажем. Метрики оценивают заданные ориентиры, а не распознают анатомию; динамика, баланс, контакты всей поверхности и сложные суставы остаются отдельными задачами.

Воспроизвести отчёты по всем намеренным ошибкам стенда, снимок лаборатории, графики и реальные кадры ориентиров: `node scripts/render-model-review.js /tmp/graph-model-review`. Скрипт не публикует файлы и не создаёт художественный ассет.

## Версия 0.8: редактирование сетки и референсы

Выбери объект → **Вершины · рёбра · грани**. В отдельном черновике доступны выбор компонентов мышью/по ID, Shift-выбор, перемещение манипулятором и числами, точные координаты вершины, выдавливание участка, удаление граней и пересчёт нормалей. Применение сохраняет всю серию одним шагом истории; отмена окна не меняет проект. Примитив преобразуется в сетку только при применении геометрических правок.

Зеркало отражает подготовленную половину относительно X/Y/Z, соединяет вершины шва с отражёнными копиями и исправляет направление граней. Это операция над сеткой; живой стек модификаторов ещё предстоит добавить.

В мастерской есть ортографические виды спереди/справа/сверху и локальные PNG/JPEG/WebP-референсы с масштабом и прозрачностью. Изображения сохраняются внутри проекта и исключаются из GLB. UV-разрывы, цвета, исходные номера вершин и ссылки ориентиров сохраняются. Новые боковины после выдавливания потребуют UV-развёртки.

API: `forge.openMeshEditor(id)`, `forge.convertToMesh(id)`, `forge.meshTopology(id)` и атомарные команды `meshEdit` / `setReferenceImages`. Полный рабочий процесс, ограничения и следующие этапы: [docs/MESH_WORKSHOP.md](docs/MESH_WORKSHOP.md).

Порядок следующих этапов и критерии готовности: [docs/ROADMAP.md](docs/ROADMAP.md).

## Версия 0.9: разрезы, объединение и фаска угла

В мастерской сетки появился раздел **Разрезы · объединение · фаска**:

- Разрезание выбранных рёбер с заданной долей длины; обе стороны UV-шва получают согласованный разрез.
- Объединение вершин в целевую точку или центр. При различии UV/цветов требуется явный выбор, какие атрибуты сохранить.
- Плоская фаска одного замкнутого выпуклого угла с проверкой допустимой ширины и замкнутости среза.
- Явный перенос затронутых ориентиров на результат вместе с геометрией, с общей отменой. Устаревшие критерии блокируют применение черновика.

Разрезание рёбер пока не является loop cut, а фаска угла не заменяет скруглённую фаску вдоль рёбер. Полная схема команд и ограничения: [docs/TOPOLOGY_TOOLS.md](docs/TOPOLOGY_TOOLS.md).


## Версия 0.10: живое зеркало

Редактирование исходной половины теперь автоматически обновляет отражённую. Модификатор можно включить, отключить, удалить или запечь в редактируемую сетку. Черновик, история проекта и сохранение сохраняют исходные данные; GLB получает вычисленную поверхность. Это первый модификатор: один mirror, без subdivision и bisect. Инструкция и API: [docs/LIVE_MIRROR.md](docs/LIVE_MIRROR.md).


## Версия 0.11: Loop subdivision и порядок модификаторов

Добавлено сглаживание треугольной сетки на 1–3 уровня с отдельным исходным каркасом. Зеркало и subdivision включаются независимо, вычисляются в выбранном порядке и запекаются вместе. Выбор граней работает по исходному каркасу, ориентиры следуют вычисленной поверхности; GLB использует тот же результат. Это Loop subdivision, без Catmull–Clark и управления жёсткостью рёбер. Подробности: [docs/SUBDIVISION.md](docs/SUBDIVISION.md).


## Версия 0.12: жёсткие рёбра

В мастерской можно помечать рёбра жёсткими и видеть их оранжевую подсветку. Loop subdivision сохраняет такие грани и углы; редактор и GLB получают настоящие разрывы нормалей. Метки сохраняются в JSON и после запекания, переносятся через разрезы и зеркало. Это двоичная жёсткость, без плавной степени и скруглённых фасок. Схема команд и ограничения: [docs/CREASES.md](docs/CREASES.md).
