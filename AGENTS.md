# Graph Forge development and asset workflow

Use the existing checkout in `/workspace/graph`. Cloud tasks are already isolated; do not create a worktree unless the user requests it.

- Install with `npm ci`, start with `npm run dev`. No application secrets, external services, databases or API keys are needed.
- Core document format, validation, atomic commands and pose interpolation: `src/document.js`.
- Simple polygon validation and default extrusion outline: `src/polygon.js`. Extrusions support concave, simple polygons, but not holes or self-intersections.
- Grouping, ungrouping, selection roots, duplication and exact TRS decomposition: `src/operations.js`. Group siblings only; preserve every clip. Reject shear rather than approximating; ungrouping animated groups requires baking and is not supported.
- Mesh validation/budgets: `src/mesh-geometry.js`; strict offline OBJ parser: `src/obj-import.js`. No MTL/texture fetching, no external file reads from OBJ directives. Preserve UVs, normals, winding and smoothing groups.
- Shared Three.js geometry and GLB generation: `src/scene.js`.
- Visual lathe-profile authoring (isolated draft + one undo step): `src/profile-editor.js`; it also edits extrusion outlines. New geometry must use the shared builder so browser, CLI and GLB agree.
- Browser editor and interaction: `src/main.js`, styling: `src/style.css`.
- CLI for generating game assets: `node scripts/forge.js`. Read README for schemas and examples.
- Prefer building assets with a `.graph.json` source plus JSON command batches. Export GLB and render PNG with the CLI, inspect the image, then refine. Do not equate successful export with verified visual quality.
- `render` and browser tests use system Chromium (`/usr/bin/chromium` here, override with `CHROMIUM_PATH`). No browser download is needed in this environment.
- Named animation clips: optional `document.clips`, managed by `src/clip-manager.js`. Legacy node.keys remains Action. Use keysFor/poseFor/clipDuration for the active clip; never sample another action as a fallback. Export rest poses plus independent glTF animation tracks.
- Undo snapshots include document, selected IDs, active object, active clip and current animation time. Keep document edits atomic, avoid history entries for no-ops, and preserve immediate autosave and recovery of corrupt browser data.
- Keep quaternion animation interpolation consistent between the viewport and GLB. Studio lights, ground, grid and selection controls are editor-only. Hidden object subtrees are omitted from GLB.
- After code changes run relevant `npm test`, `npm run test:e2e`, and `npm run build`. Do not change test expectations to conceal broken modeling or animation behavior.
- Be candid about the current scope: procedural primitives, imported triangle meshes and object transform animation, with bone nodes and linear skinning, with interactive component editing in 0.8, without automatic rigging, weight painting, UV editing/texture authoring or brush sculpting.

- Multi-selection transforms act on selected roots once. A virtual pivot lives outside the document and must never appear in exports or clean screenshots. Both helpers must be hidden for PNG capture. Keep the active track distinct from the full selection.
- The CLI imports OBJ with `node scripts/forge.js import-obj <input.obj> <output.graph.json>`. Browser `forge.importOBJ` merges into the current scene; CLI creates a new project.

- Version 0.5 adds SDF surface construction (`src/sculpt.js`), a Worker preview (`src/sculpt-editor.js`, `src/sculpt-worker.js`) and `sculpt` commands. Source recipes are optional `node.sculpt`; generated data remains canonical `mesh` geometry. Keep preview drafts isolated, reject boundary clipping, preserve shared vertices/outward normals and enforce existing mesh budgets. Vertex colors are linear RGB `geometry.colors`, exported as glTF COLOR_0.
- Separate 2D documents: `src/art-document.js` (validation, indexed pixels, compositing, paths, SVG, Aseprite-style atlas metadata), `src/art-render.js` (shared Canvas renderer), `src/art-editor.js` (layers, frames, tools, independent history/autosave). Never route 2D JSON through the 3D validator or overwrite 3D autosave. Pixel exports preserve original resolution and alpha; previews use nearest-neighbor. Atlas padding is transparent and frame durations are milliseconds.
- Asset examples are reproducible with `node scripts/build-asset-pack.js`; CLI `art-export` uses a minimal 2D-only browser page, without the 3D viewport. Inspect real PNG exports and animation frames. Vector source paths/gradients are schema validated, not arbitrary SVG/HTML. For the historical 0.5 release skeletal rigs and skinning were out of scope; 0.6 adds bones and linear skinning. UV authoring, texture painting and interactive Bezier-handle editing remain out of scope; don't claim these exist.

- Motion conventions and checks: `src/locomotion.js`. +Y up and +Z forward for Cinder; right-facing pixel Ranger advances +X. During stance the foot travels backward relative to the root and stays fixed in world space. Preserve fixed limb lengths with two-bone IK. `clip.loop: false` stops editor playback at the final pose; glTF consumers choose their own loop mode.
- Editor floor defaults to Y=0. `forge.setStage({groundY})` changes only the studio floor. Use a fitted floor for grip-centered objects; do not alter asset pivots to fix preview staging.
- Precision mesh example: `scripts/build-asterion.js`, source `examples/asterion.graph.json`. `src/mesh-audit.js` checks welded topology, normal orientation and local-X mirror matches. The spiral wrapping is intentionally asymmetric. Statistics do not measure artistic quality or UV usability.
- Agent review API: `forge.setView`, `setShading`, `captureViews`, `inspect`. Capture front/side/back/three-quarter views and inspect actual rendered silhouettes before claiming quality. Reproduce with `node scripts/render-quality-review.js`; no manual camera gestures are required.
- Pixel motion reference is optional `art.motion`; `src/motion-review.js` shows actual frames over treadmill and stationary ground. Audits measure supplied foot references, not image recognition; do not claim they automatically certify a new drawing. Horizontal flip applies to every frame and the reference, as one undo operation.

- The user explicitly prioritizes studying and improving the editor before making more artistic models. Do not add a new character to demonstrate this iteration. `src/rig-fixture.js` is a technical deformation bench only; its limit values are arbitrary test settings, not anatomical recommendations.
- Rigging research, sources, acceptance gates and limitations are saved in `docs/RIGGING_PIPELINE.md`. Treat foot locking and valid weights as engineering checks, not anatomy or AAA quality certification.
- Version 0.6: `src/skin.js` validates 4-influence skins, captures canonical bind matrices and supports exact API weight edits. Bones are regular `type: bone` nodes with existing local animation tracks. `src/scene.js` creates actual Bone/SkinnedMesh/Skeleton objects and exports skins. Never rebind while seeking or rebuilding a viewport.
- Move/animate the rig root or bones, not the skinned mesh transform. Duplicate complete rigs and remap joint IDs; deleting referenced or hiding required bones fails atomically. Hide skeleton helpers with `forge.setRigVisible` instead. Clean screenshots/GLB omit overlays.
- `src/rig-audit.js` checks author-defined hinge limits (relative to base node.rotation), local segment length drift and scale animation. It includes all bone key times and a bounded uniform grid. It does not judge anatomy, proportions, complex joint constraints or collisions. `forge.sampleRig` returns bone world positions and selected deformed world vertices for analysis.
- Weight view uses temporary cloned GPU geometry with weight colors; always dispose the clone and restore the original geometry before disposal or changing display mode. Saved document and exported colors must remain unchanged. Invalidate SkinnedMesh bounds after posing so selection, focus and raycast use deformed geometry.
- Independent Khronos validation of the technical bench is recorded in `docs/rigging-validation.json` and explained in `docs/RIGGING_PIPELINE.md`. One hierarchy warning is retained explicitly; do not claim zero warnings. The UV informational message is intentional. Never suppress validator messages just to report a clean count.

- Version 0.7: `src/review-schema.js` validates optional scene-level `document.review`; `setReview` replaces/removes it atomically. References must remain valid after deletion or clip changes. Duplicating a rig keeps scene-level review criteria on the original subject; never silently reassign them.
- `src/model-review.js` evaluates world landmarks on rigid nodes/bones and actual deformed mesh vertices. Use base TRS for rest measurements and explicit clip/time for posed measurements. Ratios and mirror planes are author-defined references, not universal anatomy rules. Sources and full conventions are in `docs/MEASUREMENTS_AND_MOTION.md`.
- Locomotion audits include all node key times, contact boundaries and gap midpoints. Separate actual root motion from virtual in-place advance. Check forward/reverse travel, trajectory and facing angle, contact drift, ground error and all declared sole points for penetration. These are sampled kinematic checks, not full-surface contact, dynamics or anatomical certification.
- `src/review-editor.js` provides draft/apply workflow and plots actual diagnostic data; invalid drafts must clear old reports. `src/review-overlay.js` displays posed points/measurement lines outside content. Clean screenshots and exports exclude this overlay unless an explicit diagnostic screenshot requests it.
- `src/review-fixture.js` is a technical block/trajectory fixture with deliberate errors. Do not present it as a new artistic character or an anatomically correct run. The user still prioritizes the editor before new character assets.

- Version 0.8: `src/mesh-edit.js` supplies shared `meshEdit` translate/setVertex/extrude/deleteFaces/mirror/recalculateNormals commands. Operate on canonical triangle buffers, preserve original vertex IDs (including unused vertices), UV and color splits, append new vertices, and recompute valid normals. Never silently weld coincident attribute seams. Bound skins require explicit unbinding; real geometry changes clear obsolete sculpt recipes.
- `src/mesh-convert.js` bakes existing shared geometry without changing node TRS/clips. Zero-area primitive triangles are omitted without reordering vertices. `convertMesh` is atomic; `forge.convertToMesh` prepares the canonical buffers.
- `src/mesh-editor.js` edits isolated local rest geometry, with component picking, translation gizmo, numeric edits and bounded draft history. Apply replays the operation series in one project commit; cancel leaves source untouched. Refuse stale drafts if source/references changed externally. Main rendering pauses behind its modal.
- The meshEdit mirror action is an applied half-mesh operation; version 0.10 adds a separate live mirror modifier. Neither supplies bisect. Reuse each seam vertex ID across reflected halves and reverse winding; reject seam caps and source vertices on the wrong side. Ignore retained unused vertices when checking sidedness. Rounded edge bevels, loop cuts, dissolve and modifier stacks remain future work; 0.9 adds a planar convex-corner bevel and explicit vertex merge.
- Optional `document.referenceImages` is schema-validated embedded PNG/JPEG/WebP data. `setReferenceImages` replaces/removes it atomically. References appear only in workshop orthographic views, in a background render pass; preserve aspect ratio, include bytes in history estimates and exclude images from GLB. UI verifies decoding and pixel/file budgets. See `docs/MESH_WORKSHOP.md` for conventions and limits.

- `src/mesh-export.js` bakes flat-shaded normals into an export-only buffer when necessary, including all vertex attributes and valid triangles. glTF has no flat-shading material flag. Keep source/viewport vertex IDs unchanged; round-trip tests must compare triangle surface positions and face normals, allowing export-only vertex splits. Existing hard-edge buffers are retained when already correct.

- Version 0.9: `src/mesh-topology.js` implements splitEdges, mergeVertices and bevelVertex inside the shared meshEdit path. Splits propagate exact Float32-position seam counterparts but preserve separate attribute slots. Merge attribute loss requires explicit target policy; reject nonmanifold/pinched/duplicate results. Bevel is one planar truncation of a closed strictly convex corner, not rounded edge beveling or collision repair.
- `editMeshGeometry` reports vertex remaps only after normal/buffer validation. `applyMeshEdit` and document commands reject affected vertex landmarks by default; explicit landmarkPolicy:remap updates them to the surviving merge target or visible bevel cap center atomically. Draft history includes landmark IDs, and topology Apply refuses externally changed review metadata.
- The workshop displays/picks only referenced vertices by default; explicit ID access and canonical unused slots remain supported. Obtain fresh edge/face IDs after topology edits. User still prioritizes editor development before new artistic characters. See `docs/TOPOLOGY_TOOLS.md`.

- Version 0.10: `src/mesh-modifiers.js` validates/evaluates one optional `node.modifiers` mirror using the existing applied-mirror kernel. Source buffers stay canonical; evaluated geometry keeps source vertex IDs as a prefix and appends reflected vertices. `scene.geometryFor` is the shared viewport/inspection/export path. Validate evaluated mesh/scene budgets and block modifiers on bound skins (including disabled settings).
- `setModifiers`/`bakeModifiers` commands are atomic; baking a disabled modifier only removes settings. Workshop drafts record modifier commands alongside geometry edits in order; history includes modifiers. Display evaluated surfaces but pick canonical components only; mirrored faces become selectable after bake. Preserve source landmark IDs and sculpt recipes until actual source changes. See `docs/LIVE_MIRROR.md`.

- Version 0.11: `src/mesh-subdivision.js` implements finite 1–3 level Loop triangle subdivision with simultaneous masks, manifold fan/winding checks, exact Float32 adjacency across attribute seams, separate linearly interpolated UV/color slots and area-weighted physical normals. Preserve source vertex slots as a prefix; unused slots stay stable. Reject evaluated growth before allocation. Do not claim Catmull–Clark, creases, volume preservation or arbitrary collision repair.
- `node.modifiers` now supports at most one mirror and one subdivision in array order, including independent disabled settings. `setLiveMirror`/`setSubdivision` preserve the other type. Bake all enabled modifiers together, remove settings, preserve vertex landmarks and clear obsolete sculpt recipes only on geometry changes. Picking subdivided faces must raycast the canonical cage, not assume evaluated face indices match source indices. Clear edge/face selection on bake; vertex IDs remain stable. See `docs/SUBDIVISION.md`.

- Version 0.12: mesh-only `geometry.creases` stores unique canonical edge endpoint pairs. `src/mesh-creases.js` validates tags, expands exact-Float32 seam counterparts and creates render-only face-fan normal splits. Keep original positions/IDs as a prefix; append copied UV/colors and map every render slot back to its canonical skin indices/weights. Never change bind matrices to accommodate shading splits. `document` validates creased shading before committing.
- Loop hard edges use midpoint children and persistent child tags; two sharp neighbors use the crease-chain mask, three or more pin the corner, and darts remain smooth. Boundary neighbors join the sharp-neighbor set. Mirror/split/merge/extrude/delete propagate surviving tags explicitly. A planar corner bevel touching tags must reject clearly, requiring explicit clearing instead of silently guessing new crease routing. UI tags are orange; history/save/bake include them. Only binary hard tags are implemented, not fractional/semi-sharp creases or rounded edge bevels. See `docs/CREASES.md`.

- Version 0.13: `src/mesh-bevel.js` adds applied `bevelEdge` for one physical edge on a closed outward convex solid (512 referenced physical vertices / 2048 source triangles maximum). Width is tangent offset along neighboring faces, segments 1–16. Reject any crease tags, multiple physical edges, concavity, open shells, and widths reaching other source vertices. General adjacent-edge miters are still absent. See `docs/ROUNDED_BEVEL.md`.
- Preserve explicit planar source/smooth interpolated source and analytic radial band normals; do not run the generic normal rebuild after bevelEdge. Refresh workshop material flatShading when geometry.smooth changes. Keep original vertex slots as a prefix, compact only unused appended slots, and publish endpoint remaps to referenced final vertices only after validation. Default landmark policy rejects; explicit remap is atomic and must be reviewed semantically. Fresh edge/face IDs are needed afterward.
- Reproduce CPU-only bevel/GLB checks with `node scripts/build-bevel-review.js`; `render-bevel-review.js` consumes those files and requires browser/localhost access. Do not claim visual acceptance from buffer checks. Current sandbox verification is documented separately from pending browser scenarios.

- Version 0.14: `src/mesh-dissolve.js` supplies `dissolveVertex` for one interior planar fan (3–64 triangles, strictly convex ring). Preserve canonical arrays and explicit normals; require one affine UV/color/normal field across the whole patch. Freeze missing smooth source normals before retriangulation. Reject seams, nonplanarity, conflicting diagonals and crease spokes; smooth meshes with any crease tags reject due topology-dependent render normals. Bound skin/active subdivision must be unbound/baked or disabled explicitly in both API and workshop. See `docs/DISSOLVE.md`.
- Dissolve keeps the unused source slot and remaps affected landmarks only with explicit policy to the nearest referenced boundary slot. Clear selection IDs and protect stale review metadata. `auditMesh` now measures only referenced surface slots for components/bounds/mirror/normals/welded count; `vertices` remains allocated count and `unusedVertices` is explicit. Do not move retained unused vertices merely to hide audit artifacts.

- The user requires convincing running mechanics for future game characters. Read `docs/RUNNING_MOTION.md` before authoring locomotion. Reuse `src/running-motion.js` only as an authored armed-run starting point, adapted to speed/proportions/load. Review complete rendered cycles and multiple angles; passing contact/IK/export checks never certifies naturalness or AAA quality. Distinguish accessible reference data from unread bibliographic sources. Do not call the pelvis proxy a measured full-body center of mass or phase-lagged weapon curves a dynamics simulation.

- For VANGUARD the user explicitly requires two-handed hip-level weapon carry. Preserve independent rifle animation under the rig root, world-space grip IK, distinct lumbar/thoracic bones and world gaze compensation. `src/secondary-motion.js` supplies a tested periodic scalar spring response; it does not simulate full-body mass/contact dynamics. Do not raise the weapon to chest/shoulder level without a new instruction.
